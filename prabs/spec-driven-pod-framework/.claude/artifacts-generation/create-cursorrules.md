# SKILL: Create .cursorrules

## Purpose
Generate a project-specific `.cursorrules` file at the project root so that DevCopilot and ReviewPilot have coding convention rules to enforce. Runs fully automatically from existing specs — no human input required.

---

## Inputs

**Required:**
- `specs/design.md` — tech stack, frameworks, coding standards, security design, observability
- `specs/program.md` — program identity, program ID, program lead

**Optional:**
- `specs/impl.md` — environment configuration, CI/CD, additional coding standards

**Template reference (structure only):**
- `references/.cursorrules`

---

## Execution

### Phase 1 — Read Specs

Read `specs/design.md` and `specs/program.md`. If `specs/impl.md` exists, read it too.

Extract the following from `specs/design.md`:

**Backend:**
- Primary language and version
- API framework
- ORM or database access library
- Type annotation requirements
- Logging library and log level conventions
- Naming conventions (variables, functions, classes, constants)
- Exception handling requirements
- Input validation approach
- Secret management rules
- Architecture boundary rules (which layers may import which)
- Any prohibited patterns

**Frontend:**
- UI framework and version
- TypeScript strictness settings
- Prohibited statements (e.g. console.log)
- Naming conventions
- Component structure requirements
- API client conventions
- Accessibility requirements
- Form validation approach

**Shared:**
- Commit message convention
- PR size guidelines
- Dead code policy
- Secret policy
- Provenance header requirement for AI-generated artifacts

### Phase 2 — Derive Rules

Map extracted information to `.cursorrules` rule statements.

For any dimension not covered in the specs, omit that section rather than inventing rules.

Mark all rules as derived from the spec — do not introduce conventions not evidenced in the source artifacts.

### Phase 3 — Generate File

Generate `.cursorrules` at the project root using the following structure (mirroring `references/.cursorrules`):

```
# .cursorrules — Coding Conventions
# Program: [program name from specs/program.md]
# Generated by: create-cursorrules skill
# Source artifacts: specs/design.md, specs/program.md
# Generated: [date]

---

## Backend ([language] / [framework])
[derived backend rules]

---

## Frontend ([framework])
[derived frontend rules — omit section if no frontend in stack]

---

## Shared
[derived shared rules]
```

---

## Output

- **File:** `.cursorrules` (project root)

---

## Post-Generation Summary

After writing the file, report inline:

- Sections generated (Backend / Frontend / Shared)
- Key rules derived per section (3–5 bullet points)
- Any spec dimensions that were absent and therefore omitted
- Flag any conventions that required inference rather than direct spec evidence — mark these `[INFERRED — validate]`
