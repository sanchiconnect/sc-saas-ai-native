# SKILL: Create AGENTS.md

## Purpose
Generate a project-specific `AGENTS.md` file at the project root so that DevCopilot and ReviewPilot have a complete AI builder guide covering project identity, source of truth, escalation triggers, compliance constraints, and provenance requirements. Runs fully automatically from existing specs — no human input required.

---

## Inputs

**Required:**
- `specs/program.md` — program name, program ID, program lead, goals, open decisions, constraints
- `specs/design.md` — architecture, tech stack, coding standards, security design
- `specs/knowledge.md` — business rules, domain constraints, roles, compliance considerations

**Optional:**
- `specs/api.md` — API boundaries and integration constraints
- `specs/database.md` — data handling constraints

**Template reference (structure only):**
- `references/AGENTS.md`

---

## Execution

### Phase 1 — Read Specs

Read `specs/program.md`, `specs/design.md`, and `specs/knowledge.md`. If `specs/api.md` and `specs/database.md` exist, read them for additional constraint signals.

Extract:

**From `specs/program.md`:**
- Program name and ID
- Program lead (name and role)
- Program purpose (1–2 sentences)
- Governing principle (primary quality/safety priority)
- Open decisions list

**From `specs/knowledge.md`:**
- Business rules that impose non-negotiable constraints on generated code
- Role definitions (RBAC)
- Compliance considerations
- System boundaries (what the system must NOT do)

**From `specs/design.md`:**
- Architecture boundary rules (which layers may access which)
- Security design decisions relevant to code generation
- Technology stack (to populate the source-of-truth spec table)

**From `specs/api.md` (if present):**
- Integration constraints (read-only vs write, external system boundaries)

**From `specs/database.md` (if present):**
- Data access constraints and sensitive field handling rules

### Phase 2 — Derive Content

Map extracted information to AGENTS.md sections:

**Project Identity** — program name, ID, lead, purpose, governing principle

**Source of Truth** — generate a table mapping each spec file to its domain (use only specs that actually exist)

**Requirement Traceability** — derive tracing requirements from provenance standards in `specs/design.md`

**Escalation** — derive escalation triggers from:
- Open decisions in `specs/program.md`
- Ambiguous or undocumented behaviours implied by business rules
- Any constraint that says the system must NOT perform an action
- Any integration boundary (read-only integrations, external systems)

**Compliance Notes** — derive from:
- Non-negotiable business rules in `specs/knowledge.md`
- Security constraints in `specs/design.md`
- Any field or data category marked as sensitive or restricted

**Provenance** — standard provenance header requirement (consistent with `.cursorrules`)

For any section where insufficient spec content exists, include the section heading with a minimal placeholder rather than omitting it.

### Phase 3 — Generate File

Generate `AGENTS.md` at the project root using the following structure (mirroring `references/AGENTS.md`):

```
# AGENTS.md — AI Builder Guide
# Program: [program name] ([program ID])
# Generated by: create-agents skill
# Source artifacts: specs/program.md, specs/design.md, specs/knowledge.md
# Generated: [date]

---

## Project Identity
[program name, ID, lead, purpose, governing principle]

---

## Source of Truth
[spec table — only include specs that exist]

If a spec is ambiguous or absent on a point required for implementation, **do not assume — escalate**.

---

## Requirement Traceability
[tracing requirements]

---

## Escalation
[escalation triggers derived from open decisions, constraints, integration boundaries]

---

## Compliance Notes
[non-negotiable constraints derived from business rules and security design]

---

## Provenance
[provenance header requirement and example]
```

---

## Output

- **File:** `AGENTS.md` (project root)

After writing the file, report inline:

- Sections generated
- Number of escalation triggers derived
- Number of compliance constraints captured
- Any business rules or constraints that required inference rather than direct spec evidence — mark these `[INFERRED — validate]`
- Any open decisions from `specs/program.md` that were incorporated as escalation triggers
