# ReleaseIntel — Output Schema

**File produced:** `artifacts/release/release-intel-report.md`  
**Version:** 2.1.0

---

## Required Sections (in order)

### 1. Report Header

```markdown
# Release Intel Report
**Sprint:** {sprint_id}
**Generated:** {date} {time}
**Scope Source:** deploy-manifest.yaml | Inferred from sprint-board.md + task-breakdown.yaml
**Artifacts Used:** [list each artifact file consumed with last-modified date if available]
```

### 2. Release Verdict Block

Must appear immediately after the header — before any other content.

```markdown
## ✅ READY TO DEPLOY  |  ❌ NOT READY — BLOCKED

**Readiness Score:** {score}/100  
**Open Blockers (P0):** {count}  
**High Risks (P1):** {count} — {acceptance_status: "n accepted by POD Lead" | "pending acceptance"}  
**Deployment Scope:** {n} components, {n} features, {n} integration points  
**Blast Radius (Overall):** LOW | MEDIUM | HIGH | CRITICAL  
```

If NOT READY, follow immediately with:

```markdown
### ❌ Gate 3 Blockers — Must Resolve Before Deployment

| # | Blocker ID | Description | Source Artifact | Resolution Required |
|---|-----------|-------------|----------------|---------------------|
| 1 | B{n}      | ...         | ...            | ...                 |
```

## Invariants

These rules must hold in every generated report:

1. **Verdict block appears before all other content** (after header only).
2. **Every blast-radius rating must cite a source artifact** with a specific section or task ID.
3. **Every P0 blocker must cite the rule ID** from `readiness-thresholds.md` (e.g., "B3").
4. **Scope source must be declared** — deploy-manifest.yaml or inferred (with method explained).
5. **No section may be omitted** — if data is unavailable, write "UNKNOWN — {reason}" rather than skipping the section.
6. **Readiness score is informational** — the binary verdict is the authoritative output.
7. **Attestation block appears last** and is always present regardless of verdict.
