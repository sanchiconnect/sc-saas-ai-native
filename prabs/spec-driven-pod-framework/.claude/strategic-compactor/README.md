# StrategicCompactor

**Lossy history digest that preserves task state.**

StrategicCompactor transforms a long conversation history into a compact structured
digest. It summarizes stale turns, collapses abandoned exploration loops, and discards
zero-information content — while preserving every actionable item verbatim: IDs,
decisions, constraints, open threads, and the current task state.

Typical reduction: 40–77% of history tokens recovered. The agent reading the output
can continue work seamlessly with no re-discovery required.

---

## When to Use StrategicCompactor vs. RelevancePruner

These two agents solve different problems. Choosing the wrong one degrades quality.

### Use StrategicCompactor when:

- **The task is in-progress.** There is live work happening, open decisions, and a
  current status that the next agent must inherit. You need to compress history without
  losing the thread of what's happening.

- **Context contains tool call chains.** CRM lookups, API calls, system responses —
  these produce dense token content that can be summarized into their final results
  without losing fidelity.

- **There are known exploration loops.** The agent tried approach A, failed, tried
  again, then pivoted to approach B. StrategicCompactor collapses loops into a single
  bullet.

- **You have structured anchors.** You know what must be kept (IDs, ticket numbers,
  dollar amounts, constraints) and you want a deterministic guarantee that these
  survive compaction.

- **The ContextProfiler alert level is `warn` or `critical`.** StrategicCompactor is
  the intended downstream agent for ContextProfiler alerts on active sessions.

### Use RelevancePruner when:

- **The task is complete.** You want to archive or compress a finished session for
  long-term storage rather than continuation.

- **You are compressing a knowledge base or reference document,** not a live session
  with open decisions.

- **Content is heterogeneous and unstructured.** RelevancePruner ranks content by
  relevance to a query or topic. StrategicCompactor ranks content by recency and
  actionability within a task.

- **There are no must-preserve anchors.** If everything is equally optional, pruning
  by relevance is more appropriate than compacting by task state.

### Rule of thumb

> If the next agent needs to pick up where this one left off → StrategicCompactor.
> If you are trimming content that is no longer needed → RelevancePruner.

## How Compaction Quality Is Assessed

StrategicCompactor self-assesses quality after compaction using a binary checklist.
The result is reported in `token-delta.json` as one of three tiers:

### `high`
All of the following are true:
- Every value in `keep-anchors.json` appears verbatim in the digest
- All `open_decisions` from anchors appear in the Open Threads section
- All `constraints` from anchors appear in the Constraints section (verbatim)
- Reduction percentage is 40% or greater
- No open thread was silently dropped
- The Task State section accurately reflects the current (not past) state

This is the expected outcome for well-structured sessions with clear anchors.

### `medium`
All anchors are preserved, but at least one of these is true:
- A nuance from the session was discarded that was not in keep-anchors.json but
  might have been contextually useful (noted in Discarded Material)
- Reduction is between 30–39%
- One non-critical decision was paraphrased rather than preserved verbatim

Acceptable when the alert level is `critical` and aggressive compaction was required.

### `low`
Any anchor was lost, or reduction is below 30%. This indicates a failure case:
- The session may not have had enough stale content to compact meaningfully
- Anchors may have been incorrectly identified
- The skill may need to be re-run with a corrected `keep-anchors.json`

A `low` quality rating should always be investigated. Do not proceed with a `low`
quality compact as the agent's sole context.

## Integration with ContextProfiler

StrategicCompactor is designed to be invoked automatically when ContextProfiler
emits a `warn` or `critical` alert on an active session.

### Trigger thresholds

| Alert Level | Utilization | StrategicCompactor Behavior |
|-------------|-------------|----------------------------|
| `info` | < 0.70 | Not triggered |
| `warn` | 0.70–0.84 | Triggered with moderate compaction target (50–60% reduction) |
| `critical` | 0.85–0.94 | Triggered with aggressive compaction target (65–75% reduction) |
| `overflow` | ≥ 0.95 | Emergency compaction — discard everything except anchors |

### Integration workflow

```
ContextProfiler alert (warn/critical)
        ↓
StrategicCompactor reads:
  - full-session.md         (from session history export)
  - keep-anchors.json       (generated by ContextProfiler anchor extraction)
  - context-profiler-alert.json (the triggering alert)
        ↓
StrategicCompactor produces:
  - compacted-context.md    (replaces raw history in agent context)
  - retained-anchor-manifest.json (audit trail)
  - token-delta.json        (metrics for ContextProfiler feedback loop)
        ↓
Agent continues with compacted-context.md injected as replacement for history
```

ContextProfiler uses `token-delta.json` from previous compactions to improve its
anchor extraction quality over time. If `compaction_quality` is `medium` or `low`,
ContextProfiler should adjust its anchor weighting for the next session.

### What ContextProfiler provides

The `keep-anchors.json` that ContextProfiler generates for StrategicCompactor should
always include:
- All entity IDs mentioned more than once in the session
- All monetary amounts that are subject to decisions
- The most recently stated task status
- All constraints that were explicitly mentioned (SLA, policy references, thresholds)
- All open decisions that were named but not resolved

If ContextProfiler omits any of these, StrategicCompactor will still attempt to
identify anchors from the raw session, but the quality guarantee is weaker.

## Output Files Reference

| File | Purpose | Consumed By |
|------|---------|-------------|
| `compacted-context.md` | The structured digest — replaces raw history | Downstream agents |
| `retained-anchor-manifest.json` | Audit trail of what was kept and why | ContextProfiler, debugging |
| `token-delta.json` | Token metrics and quality score | ContextProfiler, monitoring |

## Limitations

**Summarization is lossy.** Subtle context that was not explicitly anchored — a tone
shift in the customer's messages, an implicit assumption the agent made, an unresolved
ambiguity — may be discarded. This is an accepted trade-off.

**Anchor selection bounds fidelity.** The quality of compacted-context.md is only
as good as the keep-anchors.json provided. If critical items are missing from the
anchors file, they may be treated as stale and discarded. Always review
keep-anchors.json before running compaction on high-stakes sessions.

**Over-aggressive compaction compounds errors.** If StrategicCompactor discards
something that turns out to be important, the next agent has no way to recover it
from context — it must re-derive it from tools or ask the customer again. In
customer-facing sessions, this causes friction. Err toward preserving ambiguous items
in the Open Threads section rather than discarding them.

**Not a replacement for tool re-calls.** For truly critical data (current account
balance, live system status), always re-call the tool rather than relying on a
compacted summary of a prior tool response. Compacted context captures state at the
time of compaction, not real-time state.
